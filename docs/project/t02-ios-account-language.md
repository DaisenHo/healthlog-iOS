# T02：iOS 账户语言

对应 [iOS #1](https://github.com/DaisenHo/healthlog-iOS/issues/1)，依赖服务端 T01 的账户语言接口。

## 使用流程

在“更多 → 设置 → 账户 → 语言”选择语言。账户语言与 Web 和后台日报共用；只有服务端确认保存后，界面才采用新选择。失败保留上一次确认的语言，并显示错误。

未登录时使用系统语言；登录后读取账户语言。已确认的语言按服务地址与登录账户缓存，冷启动和离线时恢复。离线可阅读，修改需要联网；恢复连接或回到前台后重新读取服务端。退出登录清除语言缓存并恢复系统语言。

语言选择不改变计量单位、时区、时间格式、健康记录或提醒设置。共享档案的访问者修改自己的账户语言，不修改档案所有者。

本任务提供账户语言机制和选择器的简体中文文案。各功能完整中文翻译、报告模板和小组件翻译仍由后续任务负责；缺少翻译时保留英文回退。临床问卷继续采用已有授权的德文或英文版本。

## 实现约定

- `SettingsRepository` 调用 `GET/PUT /api/auth/me/locale`；PUT 只提交 `{ locale }`，不重试、不自动更换认证身份。
- `SettingsStore` 使用当前会话租约、冻结的认证头及请求版本号，拒绝退出登录前或显式选择前的旧响应。
- `AppLocale` 向 SwiftUI 提供环境语言，向 Foundation 提供 `LocalizedStringResource.locale`。不能仅设置 `String(localized:locale:)`，该参数只控制插值格式，不选择资源语言。
- 需要显式语言的既有接口仍可覆盖默认账户语言，缺失翻译时同样保留英文回退。偏好缓存保存服务地址指纹，不复制 Keychain 中的私有服务地址。
- 现有 Foundation 文案调用改用 `AppLocale.string`，保留编译期字符串提取。日期显示采用当前账户语言；数值输入解析及显式单位、时区偏好保留原约定。
- 不增加依赖，不改变 iOS 18 最低版本及 CI 的 Xcode 26.6 固定版本。

## 验证入口

- `AccountLanguageTests`：语言代码映射、实际资源查找、访客回退、缓存归属。
- `SettingsStoreLanguageTests`：确认保存、重启恢复、保存失败、恢复联网、响应不一致、旧 GET 与旧账户 PUT 的并发隔离。
- `AccountLanguageLiveTests`：可选的本地真实服务契约测试，原生客户端 PUT 后核验账户 GET。仅接受 localhost/127.0.0.1，需通过 `TEST_RUNNER_T02_SERVER_URL`、`TEST_RUNNER_T02_TOKEN` 传入隔离测试配置。
- `AccountLanguageUITest`：真实登录、德语系统下切换英文/简体中文、重启保留。另需 `TEST_RUNNER_T02_EMAIL`、`TEST_RUNNER_T02_PASSWORD`，使用虚构账户；没有配置时明确跳过，不连接外部服务。

本地安装的是 Xcode 27.1，最终验证结果与未通过的门禁记录在本次任务报告中；不能据此声称已在 CI 固定工具链或 iOS 18 真机上验证。

### 工具链与规范记录

本地 Xcode 27.1 要求两处嵌套异步闭包显式捕获外层引用，因此在 `PinToHomeContextMenu` 和 `AppContainer+FeatureFlags` 补上捕获列表，保留原有内部弱引用和任务行为。

SwiftLint 仍为原有 272 条警告、0 错误；配置和阈值不变。基线仅更新受机械换行和新增语言状态影响的指纹：`SettingsStore` 类型长度增加 12 行，其他既有文件或函数因换行及显式显示语言设置产生长度指纹变化，其余为位置移动或长度缩减，没有新增规则豁免。

Xcode 27.1 的 SwiftPM 默认构建引擎变为 `swiftbuild`，原核心门禁按旧日志的 `Compiling HealthLogCore` 计数会误报零文件。默认构建成功；显式使用原 `native` 引擎也成功，编译 412 个文件。保留原门禁，仍需固定 CI 工具链验证。

- SwiftFormat、SwiftLint（272 条既有警告、0 错误）、本地化与字符串目录、标点、函数长度、敏感信息扫描及核心构建通过。原 SwiftPM 编译计数门禁仍有上述新工具链日志兼容限制。
